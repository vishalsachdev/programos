# Weekly Quality Review

This skill runs as a scheduled task. It analyzes the week's audit logs and eval data to identify patterns, gaps, and improvement opportunities.

## Workflow

1. **Read eval summary** from `/workspace/ipc/eval_report.md` (generated by the host before this task runs). If the file is missing or shows 0 responses, note this and proceed with audit log analysis only.
2. **Read this week's audit logs** from `/workspace/extra/program-repo/discussions/audit-log/`. Files are named `YYYY-MM-DD.md`. Each entry is a markdown section with timestamp, channel, direction (inbound/outbound), sender, and message content, separated by `---` dividers.
3. **Read the current FAQ** from `/workspace/extra/program-repo/docs/faq.md` (if it exists)
4. **If no audit logs or eval data exist for the period**, write a brief "No data available for this period" report and exit.
5. **Analyze patterns:**
   - Which topics have recurring low-confidence answers?
   - Are there questions being asked repeatedly that should be in the FAQ?
   - Which channels generate the most questions? Are responses appropriate for each channel's format?
   - Are citation rates acceptable? Where are gaps in documentation?
   - Are there topics frequently asked about that aren't well covered in the repo?
6. **Generate report** and save to `/workspace/extra/program-repo/discussions/QUALITY_REVIEW.md`
7. **Commit and push** the report:
   ```bash
   cd /workspace/extra/program-repo
   git config user.name 'Coordinator'
   git config user.email 'program-bot@example.org'
   git add discussions/QUALITY_REVIEW.md
   git commit -m "quality-review: weekly report $(date +%Y-%m-%d)"
   git push
   ```

## Report Format

```markdown
# Quality Review — Week of YYYY-MM-DD

## Summary
- Total responses: N
- Confidence: X% high, Y% medium, Z% low
- Citation rate: N%

## What's Working Well
- [bullet points about strong areas]

## Needs Improvement
- [bullet points about weak areas with specific examples]

## Recommended Actions
- [ ] [Specific action items for the team — e.g., "Add financial aid FAQ to repo"]
- [ ] [e.g., "Update courses/PRG502.md with latest prerequisites"]

## Knowledge Gaps
Topics where the agent couldn't find good answers:
- [topic]: asked N times, confidence low
```

## Rules

1. **Commit the report** — commit and push so it persists in the repo
2. **Be specific** — cite actual questions from audit logs, not vague observations
3. **Be actionable** — every "needs improvement" item should have a matching recommendation
4. **Compare to last week** if a previous QUALITY_REVIEW.md exists — note trends
